# Project working instructions

- Respond to the owner in Thai; the owner may write in English.
- Focus on developing and testing the Java game.
- Current development order: gameplay first, then sound effects/music, then art/graphics, and documentation last. Keep the existing theme choices undecided until the owner chooses; do not finalize a theme implicitly.
- The owner will write the academic report. Do not create or update reports unless explicitly asked. Explain the OOP concepts when requested.
- Preserve the existing report, guides and presentation notes as historical Version 1 artifacts.
- Preserve named version snapshots. Never modify an existing snapshot to reflect later changes.
- By default, keep future version history on GitHub. Do not create additional local snapshot folders or full-backup ZIPs unless the owner explicitly asks again. Keep the current working project and existing v1.0.0 backup; do not delete them.
- A saved local edit is not automatically on GitHub. After an agreed game change is tested, commit and upload the version with the relevant playable package and assets, and verify the upload before reporting it saved online.
- When asked to back up a version, include the full project source, source ZIP, Windows play ZIP and JAR, existing guides, presentation notes, existing reports, and available screenshots. Verify the backup contents and checksums.
- Version 1 is v1.0.0. Future GitHub versions should use commits, version tags and Release assets rather than committing duplicate snapshot directories.
- Do not publish a repository or change repository visibility without the owner's chosen destination and visibility.
