# กติกาของ Type Strike เวอร์ชันแรก

## ขอบเขต

เกม Desktop บน Windows ใช้ Java 21 และ Swing มีฐานกลางสนาม ศัตรูจากขอบทั้งสี่ด้าน และการพิมพ์คำเพื่อโจมตี ใช้การตัดสินใจเลือกคำจากระยะห่าง ความเร็ว และจำนวนครั้งที่ต้องโจมตี ระบบเกราะเป็นข้อเสนอเพิ่มอุปสรรคจากแนวคิดเดิม ยังไม่ได้รับการยืนยันเพิ่มเติมจากอาจารย์

## ค่าตั้งต้น

| รายการ | ค่า / ตำแหน่งแก้ไข |
|---|---|
| พลังชีวิตฐาน | 100 ใน `Base.MAX_HEALTH` |
| สนามพิกัดตรรกะ | 1100×540 ใน `GameModel` |
| เวลาเกิดตัวแรก | 0.8 วินาที |
| ช่วงเวลาเกิด | max(0.7, 2.2 - เวลาที่เล่น / 120) วินาที |
| จำนวนศัตรูสูงสุด | 14 ตัว |
| ความเร็วตามคำ | clamp(190 / (ความยาวคำ + 1), 22, 56) หน่วยต่อวินาที |
| ความเร็วเพิ่มตามเวลา | คูณ 1 + min(0.8, เวลาที่เล่น / 180) |
| ความเร็วศัตรูเกราะ | 80% ของค่าปกติ แม้เกราะแตกแล้ว |
| ระยะชนฐาน | 36 หน่วยจากจุดศูนย์กลาง |
| ความเสียหาย | ความยาวคำที่ศัตรูถืออยู่ตอนถึงฐาน |
| คะแนนปกติ / เกราะ | 10 / 25 คะแนนต่อการกำจัด |
| การเริ่มปรากฏของเกราะ | ตัวที่ 6 และโอกาส 28% หลังจากนั้น |
| Level | เพิ่มทุก 30 วินาทีเพื่อบอกความคืบหน้า ความยากจริงเพิ่มต่อเนื่อง |

เวลาที่ใช้คำนวณเป็นเวลาจำลองระหว่างเกมทำงาน ไม่รวม Pause และแต่ละเฟรมจำกัด delta ไว้ที่ 0.1 วินาที เพื่อป้องกันการกระโดดของตำแหน่งเมื่อหน้าต่างค้างชั่วคราว

## การรับคำและการเลือกเป้าหมาย

Enter จะส่งข้อความทั้งคำ ไม่โจมตีทีละตัวอักษร ตัดช่องว่างหัวท้ายและแปลงเป็นตัวพิมพ์เล็ก การส่งช่องว่างไม่ถูกนับเป็นการพยายาม คำที่ไม่ตรงจะนับว่าไม่สำเร็จและไม่หัก HP ทันที คำศัพท์ไม่ซ้ำกันระหว่างศัตรูที่อยู่บนสนาม รวมถึงคำใหม่หลังเกราะแตก จึงจับคู่ได้หนึ่งตัวอย่างแน่นอน

การทำลายเกราะไม่เพิ่มคะแนนและไม่คืน HP มีเอฟเฟกต์และข้อความบอกให้พิมพ์คำใหม่ ศัตรูยังเคลื่อนที่ต่อ หากตัวเกราะถึงฐานก่อนกำจัดจะหัก HP ตามความยาวคำปัจจุบันเพียงครั้งเดียว

## การแสดงผลและการย้ายเครื่อง

ขนาดหน้าต่างเริ่มต้น 1140×820 และขนาดต่ำสุด 960×720 สนามใช้การย่อขยายตามสัดส่วนและมีขอบว่างเมื่ออัตราส่วนเปลี่ยน จึงไม่เปลี่ยนความเร็วเกมเมื่อย่อหน้าต่าง ป้ายคำพยายามเลื่อนเพื่อหลบการซ้อนและเชื่อมเส้นไปยังตัวศัตรู แต่ในจุดที่หนาแน่นมากยังอาจมีการซ้อนได้

ไฟล์ words.txt โหลดผ่าน Resource ใน JAR ข้อมูลคะแนนแยกไปอยู่ในโฟลเดอร์ผู้ใช้ ไม่อ้างอิงพาธ Desktop ของเครื่องพัฒนา การย้ายเฉพาะ JAR ไม่ได้ย้ายสถิติคะแนนเดิมไปด้วย

## การเปลี่ยนงานภาพ

1. วาดศัตรูและฐานบน iPad หรือโปรแกรม Pixel Art ที่ใช้ถนัด ส่งออกเป็น PNG โปร่งใส
2. เริ่มจากศัตรู 32×32 และฐาน 64×64 โดยคงสเกลพิกเซลให้เข้ากัน
3. วางไฟล์ใต้ resources/art และปรับ Build ให้คัดลอกทรัพยากรเหล่านั้นเข้า JAR
4. เปลี่ยน `PixelArt` ให้โหลดผ่าน `getResourceAsStream()` และวาดด้วย nearest-neighbor
5. ไม่วางคำศัพท์ไว้ในรูป เพราะคำต้องเปลี่ยนตามกติกา ให้ UI วาดแยกเช่นเดิม
6. หากใช้ Asset ภายนอก เพิ่มแหล่งที่มาและสัญญาอนุญาตในรายงานและ Repository

## ข้อจำกัดที่ทราบ

- ยังไม่มีเสียง ดนตรี Animation แบบ Sprite Sheet และหน้าตั้งค่า
- ความยากเป็นค่าตั้งต้น ต้องปรับหลังผู้จัดทำทดลองเล่นจริง
- ไม่มีระบบออนไลน์ บัญชีผู้เล่น หรือสถิติ WPM
- ใช้ภาษาอังกฤษบนหน้าจอเพื่อไม่ให้ขึ้นกับฟอนต์ไทยบนเครื่องปลายทาง รายงานและคู่มือเป็นภาษาไทย
- คะแนนอยู่ในเครื่องผู้ใช้และแก้ไขได้ด้วย Text Editor ไม่ใช่ระบบแข่งขันที่ป้องกันการโกง
- ยังไม่ทดสอบบน Notebook เครื่องที่จะนำเสนอ
