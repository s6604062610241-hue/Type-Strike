# แนวทางเตรียมนำเสนอ Type Strike

กำหนดนำเสนอ 4 พฤศจิกายน 2026 ควรทดลองบน Notebook จริงก่อนวันนั้น โดยใช้ไฟล์ที่ดาวน์โหลดจาก Repository หรือไฟล์ส่งมอบ ไม่ใช้พาธจากเครื่องพัฒนา

## ลำดับสาธิตประมาณ 5 ถึง 7 นาที

1. อธิบายโจทย์ เกมฝึกพิมพ์ที่ต้องป้องกันฐานกลางจอและเลือกจัดการศัตรูตามความเร่งด่วน
2. เปิด Menu อธิบาย High Score และเริ่มเล่น พิมพ์คำถูกหนึ่งคำ แสดงคะแนนและตัวอักษรสีเขียว
3. สาธิตศัตรูเกราะ คำแรกแตกเกราะ คำใหม่ใช้กำจัด อธิบายว่าเพิ่มการวางแผนจากเดิม
4. พิมพ์ผิด แสดงว่าไม่หัก HP โดยตรง แต่เวลายังเดิน กด Escape เพื่อ Pause แล้ว Resume
5. เปิดโค้ด `Base`, `Enemy`, `NormalEnemy`, `ArmoredEnemy` และ `GameModel.submit()` เพื่ออธิบาย OOP
6. เปิด `PlayScreen` เพื่อชี้ Event Handling และการแยก update ออกจาก paintComponent
7. แสดงผลการทดสอบ ไฟล์ JAR และ Repository ปิดด้วยข้อจำกัดและสิ่งที่พัฒนาต่อได้

## คำถามที่ควรตอบให้ได้

**ทำไมต้องเป็น abstract Enemy?** เพราะศัตรูทุกชนิดมีพิกัด คำศัพท์ และการเคลื่อนที่ร่วมกัน แต่ตอบสนองเมื่อพิมพ์ถูกต่างกัน

**Polymorphism อยู่ตรงไหน?** ใน `GameModel.submit()` เรียก onWordMatched ผ่านตัวแปร Enemy แล้ว Java เลือกเมธอดของ NormalEnemy หรือ ArmoredEnemy

**Composition ต่างจาก Inheritance อย่างไร?** GameModel มี Base และศัตรู เป็นความสัมพันธ์ has-a ส่วน ArmoredEnemy เป็น Enemy เป็นความสัมพันธ์ is-a

**ทำไมไม่ใช้ Thread แยกทุกศัตรูเหมือนตัวอย่าง?** เกมนี้ใช้ Swing Timer อัปเดตทุกตัวบน EDT เดียว ทำให้การรับคำ การลบศัตรู และการวาดภาพไม่แย่งแก้รายการศัตรูพร้อมกัน

**ทำไมคะแนนไม่เพิ่มตอนเกราะแตก?** ให้คะแนนต่อการกำจัดเท่านั้น ศัตรูเกราะได้มากกว่าเพราะใช้สองคำ

**คะแนนเก็บที่ไหน?** โฟลเดอร์ผู้ใช้ .type-strike/scores.txt แยกจาก JAR และ Source Code

**รู้ได้อย่างไรว่าเกมทำงานถูก?** มีการทดสอบกติกาและการบันทึกอัตโนมัติ แต่ความสนุก ความอ่านง่าย และความยากยังต้องทดสอบกับผู้เล่นจริง

## ตรวจบน Notebook

- ติดตั้ง Java 21 หรือใหม่กว่า ตรวจ java -version และ javac -version หากต้อง Build
- เปิดเกมจาก JAR ได้แม้ไม่มีโฟลเดอร์ src อยู่ข้างกัน
- ทดสอบภาษาแป้นพิมพ์อังกฤษ การกด Enter, ปุ่ม CAST และ Escape
- ทดสอบศัตรูปกติ เกราะ ความเสียหาย Game Over และ Play Again
- ปิดเปิดเกมแล้วคะแนนยังอยู่ ตรวจความละเอียดจอและ Display Scaling
- เปิดเอกสารและ Repository ได้ เตรียมสำเนาออฟไลน์ของ JAR, Source ZIP และรายงาน
- อ่านโค้ดให้เข้าใจและปรับข้อความรายงานให้ตรงกับสิ่งที่ทดลองเอง ไม่อ้างผลการทดสอบผู้เล่นที่ยังไม่ได้ทำ
